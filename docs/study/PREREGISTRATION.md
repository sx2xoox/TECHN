# 사전 등록 양식 (AsPredicted 형식)

본 실험의 첫 참가자를 받기 **전에** [AsPredicted](https://aspredicted.org) 나 [OSF](https://osf.io) 에 등록하세요. `[ ]` 칸은 예비 실험 뒤에 채웁니다. 그 밖의 내용은 [PROTOCOL.md](PROTOCOL.md) 와 같아야 합니다.

**1. 이미 자료를 모았습니까?**
아니요. 예비 실험(`?pilot=1`, 분석에서 자동 제외) 자료만 있으며, 이는 화면 점검과 표본 크기 계산에만 썼습니다.

**2. 주 질문·가설은 무엇입니까?**
개발 경험이 없는 성인은 같은 데이터에서 규칙을 어긴 곳을 찾을 때, 픽셀 마을 표현(세계)에서 관리자 표(대시보드)보다 빨리 찾는다(H1). 판정 기준: 참가자별 '세계/표' 정답 시간 비율 중앙값의 부트스트랩 95% 구간 상한이 0.5 이하이면 "50% 이상 단축"(KPI) 달성.

**3. 주 종속 변수는 무엇이며 어떻게 잽니까?**
정답 과제(어긴 곳을 맞게 고른 과제와 '위반 없음'을 맞게 고른 과제)에서 과제 화면이 그려진 순간부터 제출까지 걸린 시간(ms, 브라우저 `performance.now()`). 참가자·조건마다 중앙값을 구합니다.

**4. 조건은 몇 개이며 무엇입니까?**
참가자 안 2조건: (a) 세계(ISOMORPH 픽셀 마을, 말풍선에 원본 값만), (b) 표(요약 카드 + 정렬되는 테이블). 조건 순서는 참가 번호의 짝·홀로 번갈아 정합니다. 조건마다 연습 1개(정답 공개)와 본 과제 5개(위반 4종 + 없음 1)를 풉니다. [선택: 3조건으로 하면 (c) 표 + 위반 행 강조를 추가하고, 세계 대 (c) 는 탐색 분석으로 둡니다.]

**5. 가설을 검정할 분석은 무엇입니까?**
- 비개발자(배경 질문 '없음') 완료 참가자에서 참가자별 중앙 시간을 짝지은 윌콕슨 부호 순위 검정(양측, α=0.05; n≤25 는 정확 분포)과 효과 크기 r.
- 비율 중앙값의 부트스트랩 95% 구간(4,000회, 시드 7).
- 분석 코드: 이 저장소 커밋 `[커밋 해시]` 의 `npm run study:analyze`.

**6. 이상치·제외는 어떻게 정의합니까?**
- **분석에서 뺄 참가자**: 예비 참가자, 미완료자, 그리고 사전 기준 위반자입니다. 위반 기준은 (1) 기술 문제로 중단·재시작, (2) 진행자가 과제 내용을 도움, (3) 선별 기준 불충족이 드러남이며, 진행자 화면에 사유를 기록합니다.
- **시간 비교에서만 뺄 참가자**: 한 조건에서 정답이 하나도 없는 참가자는 시간 비교에서만 빠지고 정확도 분석에는 남습니다.
- 결과를 보고 빼지 않으며, 시간 이상치를 따로 잘라내지 않습니다(중앙값을 쓰므로).

**7. 표본 크기는 얼마이며 어떻게 정했습니까?**
비개발자 완료 참가자 `[N]`명입니다. 예비 실험에서 비율 중앙값 `[r]`, 로그 표준편차 `[s]` 를 얻었고, `npm run study:power -- [r] [s]` 에서 KPI 판정 확률이 80% 이상인 가장 작은 N 입니다(기본 가정 0.35·0.5 에서는 24명). 분석 대상이 N명이 되면 멈춥니다.

**8. 그 밖에 미리 밝혀 둘 것**
- **부 분석**: 위치·원인 정확도, 역효율 점수, 노력·확신(1–7), 선호, 개발 경험 집단별 결과, 조건 순서 효과.
- **공개**: 결과는 방향과 관계없이 공개합니다. KPI 미달도 그대로 보고합니다.
- **설계자 편향**: 화면과 과제를 만든 팀이 실험을 진행합니다. 이를 줄이려고 같은 규칙 카드, 원본 값만 보이는 말풍선, 정답 비공개 서버 채점을 씁니다.
