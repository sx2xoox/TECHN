# 연구 계획서: 세계(ISOMORPH) 대 표(대시보드)에서 규칙 위반 찾기

판: 1.0 · 도구: `npm run study`(이 저장소의 같은 커밋) · 이 문서는 본 실험 전에 고정하고, 바꾸면 바뀐 날짜와 이유를 아래 '변경 기록'에 남깁니다.

## 1. 연구 질문과 가설

**질문**: 소프트웨어 개발 경험이 없는 성인이 시스템 데이터에서 규칙을 어긴 곳을 찾을 때, 픽셀 마을 표현(세계)이 흔한 관리자 화면(표)보다 빠르고 정확한가?

- **H1(주 가설, 시간)**: 정답을 맞힌 과제에서 걸린 시간은 세계가 표보다 짧다.
- **H1-KPI(판정 기준)**: 참가자별 '세계 중앙 시간 / 표 중앙 시간' 비율의 중앙값에 대한 95% 부트스트랩 구간 상한이 0.5 이하다(= 50% 이상 단축).
- **H2(부 가설, 정확도)**: 어긴 곳을 맞게 고른 비율은 세계가 표보다 낮지 않다.
- **탐색**: 원인(어긴 규칙) 정확도, 포기·시간 초과율, 정신적 노력·확신(1–7), 선호. 3조건으로 진행하면 세계 대 '표 + 위반 강조'도 봅니다.

## 2. 설계

- **참가자 안 비교**: 모든 참가자가 두 조건(세계, 표)을 모두 겪습니다. 조건 순서는 참가 번호로 번갈아 정해집니다(짝수: 세계 먼저, 홀수: 표 먼저).
- **과제**: 같은 쇼핑몰 데이터(상품 10~13, 고객 8~11, 주문 14~21)에 규칙 위반 하나를 심거나 심지 않은 정적 장면입니다.
  - 위반은 4종입니다: 재고 음수, 없는 상품을 가리키는 주문, 시간이 거꾸로 간 주문, 같은 번호의 상품 중복.
  - 조건마다 4종과 '위반 없음' 1개를 한 번씩, 모두 5과제를 봅니다. 장면은 참가자·과제마다 시드로 만들어 겹치지 않습니다.
- **연습**: 조건마다 1과제를 먼저 풀고, 이때만 정답을 알려줍니다. 본 과제에서는 알려주지 않습니다.
- **답하는 법**: 어긴 곳(행·건물·주민)을 고르고 어긴 규칙을 고른 뒤 제출합니다. '어긴 곳이 없다'를 고를 수도 있고, '모르겠어요'로 넘어갈 수도 있습니다. 제한 시간은 2분이며, 넘기면 시간 초과로 기록합니다.
- **공정성**:
  - 두 조건 모두 같은 '이 시스템의 규칙' 카드를 항상 보여줍니다.
  - 세계의 말풍선은 원본 값만 보여줍니다(경고 문구 없음).
  - 표는 요약 카드와 정렬되는 표가 있는 평범한 관리자 화면입니다.
  - 안내와 연습의 분량은 두 조건이 같습니다.

## 3. 참가자

- **대상**: 만 19세 이상, 소프트웨어 개발을 업무로 하지 않는 사람. 화면의 글자와 색을 읽는 데 어려움이 없어야 합니다.
- **주 분석 대상**: 배경 질문의 개발 경험이 '없음'인 참가자. '조금'·'업무'로 답한 참가자는 따로 분석합니다(부 분석).
- **표본 크기**: 비개발자 완료 참가자 N명. N 은 예비 실험 후 `npm run study:power` 로 정합니다. 기본 가정(비율 0.35, 로그 표준편차 0.5)에서는 KPI 판정 확률 80% 에 약 24명입니다. 사전 등록 때 숫자를 고정합니다.
- **멈추는 규칙**: 분석 대상 완료자가 N명이 되면 모집을 멈춥니다. 중간에 결과를 보고 N 을 바꾸지 않습니다.

## 4. 환경

- 같은 노트북과 마우스를 씁니다(터치패드 금지). 화면은 1440×900 이상, 브라우저 확대 100%, 조용한 방.
- 실험 서버는 진행자 노트북에서 돌립니다(`npm run study`). 원격으로 할 때는 참가 코드를 쓰고, 화면 크기와 입력 장치를 기록합니다(도구가 화면 크기를 자동으로 기록).

## 5. 절차(약 15~20분)

| 단계 | 시간 | 내용 |
|---|---|---|
| 맞이 | 2분 | 대본 A, 설명문 전달, 질문 받기 |
| 동의 | 2분 | 인쇄 동의서 서명 + 화면 동의 |
| 배경 | 1분 | 개발 경험, 표 사용 빈도, 연령대(선택) |
| 첫 조건 | 5~7분 | 안내 → 연습(정답 공개) → 본 과제 5개 → 설문(노력·확신) |
| 둘째 조건 | 5~7분 | 같음 |
| 마무리 | 2분 | 선호·의견, 참가 번호 안내, 대본 B(사후 설명) |

## 6. 진행자 대본

**대본 A(시작)**
> 오늘은 프로그램 화면 두 가지를 비교하는 실험입니다. 평가 대상은 여러분이 아니라 화면입니다. 화면에 어떤 가게의 데이터가 나오는데, 그 안에서 규칙을 어긴 곳을 찾으시면 됩니다. 규칙은 화면 왼쪽에 계속 보입니다. 어긴 곳이 없을 수도 있습니다. 가능한 한 빠르고 정확하게 해 주세요. 과제 중에는 제가 도와드릴 수 없지만, 화면이 멈추거나 이상하면 말씀해 주세요. 언제든 그만두셔도 됩니다.

**과제 중**
- 화면 조작법(누르기, 끌기, 휠)만 다시 말해 줄 수 있습니다. 어디를 보라거나 무엇이 문제라는 말은 하지 않습니다.
- 소리 내어 생각하기는 시간이 달라지므로 요청하지 않습니다.
- 기술 문제(멈춤, 새로고침)가 나면 시각과 내용을 점검표에 적습니다. 새로고침하면 처음부터 다시 해야 하며, 그 세션은 기술 문제로 제외합니다(아래 7절).

**대본 B(끝)**
> 감사합니다. 이 실험은 마을처럼 그린 화면이 표보다 문제를 찾기 쉬운지 알아보려는 것이었습니다. 참가 번호는 ○번입니다. 나중에 기록을 지우고 싶으시면 이 번호로 연락 주세요. 다른 분들이 참여하기 전까지는 실험 내용을 말하지 말아 주세요.

## 7. 분석 계획

- **분석 대상**: 본 실험 참가자 중 완료자. 예비·제외·미완료 참가자는 뺍니다(도구 기본값).
- **사전에 정한 제외 기준**(진행자 화면에서 사유를 적어 표시):
  1. 기술 문제로 과제가 중단·재시작됨.
  2. 실험 중 진행자가 과제 내용을 도와줌(절차 위반).
  3. 참가자가 선별 기준을 충족하지 않음이 나중에 드러남(예: 개발 업무 종사).
  - 결과(시간·정확도)를 보고 제외하지 않습니다.
- **주 분석**: 비개발자 참가자에서 참가자별 '정답 과제 중앙 시간'을 조건별로 구하고 짝지어 비교합니다.
  - 윌콕슨 부호 순위 검정(양측, α=0.05; 25명 이하는 정확 분포)과 효과 크기 r 을 냅니다.
  - 비율 중앙값의 부트스트랩 95% 구간(4,000회, 시드 고정)을 냅니다.
  - H1 은 p<0.05 이고 비율 중앙값이 1보다 작을 때 지지됩니다. KPI 는 구간 상한이 0.5 이하일 때만 달성입니다.
- **한 조건에서 정답이 하나도 없는 참가자**: 시간 비교에서 빠지고, 보고서에 그 수를 적습니다. 정확도 분석에는 포함합니다.
- **부 분석**: 위치·원인 정확도(조건별 비율과 참가자별 짝 비교), 역효율 점수, 노력·확신, 선호, 개발 경험 집단별 결과, 조건 순서 효과(먼저 본 조건별로 나눠 비교).
- **도구**: `npm run study:analyze -- data/study --out report.md --csv trials.csv`. CSV 로 다른 통계 도구에서 다시 확인할 수 있습니다.

## 8. 위험과 한계

- **최소 위험**: 화면을 보고 누르는 과제뿐입니다. 피로를 줄이려고 전체를 20분 안팎으로 맞췄습니다.
- **색 의존**: 세계의 일부 표현은 색에 기댑니다. 색각 이상이 있는 참가자를 따로 보지는 않으며, 한계로 보고합니다.
- **일반화**: 결과는 이 쇼핑몰 장면, 이 4종 위반, 이 표 디자인에 한정됩니다. 실제 운영 환경, 더 큰 데이터, 다른 위반으로 일반화하려면 별도 실험이 필요합니다.
- **설계자 편향**: 과제와 두 화면을 같은 팀이 만들었습니다. 그래서 같은 규칙 카드, 원본 값만 보이는 말풍선, 세 번째 조건(표 + 위반 강조)으로 줄이려 했고, 표 디자인 개선안이 있으면 받아들입니다.
