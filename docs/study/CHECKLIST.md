# 회차 점검표

## 실험 전(그날 처음 한 번)

- [ ] 사전 등록을 마쳤고, 등록한 커밋에서 `npm install && npm run build` 를 했다.
- [ ] `npm run study:selftest` 가 통과한다(도구 자가 시험, 기록은 임시 폴더에만 남음).
- [ ] `npm run study` 를 실행하고, 진행자 화면 주소를 참가자에게 보이지 않는 곳에 열어 두었다.
- [ ] 노트북 화면 1440×900 이상, 브라우저 확대 100%, 마우스 연결, 알림 끄기.
- [ ] 인쇄한 설명문·동의서, 펜.

## 회차마다

- [ ] 브라우저 새 창(또는 시크릿 창)에서 `/study` 를 열었다. 예비 실험이면 `/study?pilot=1`.
- [ ] 대본 A 를 읽고, 동의서에 서명을 받았다.
- [ ] 참가자가 화면 동의 → 배경 질문을 직접 했다(진행자가 대신 고르지 않음).
- [ ] 과제 중에는 조작법만 답했다. 어디를 보라는 말은 하지 않았다.
- [ ] 기술 문제가 있었다면 시각과 내용을 적었다: ____________________
- [ ] 마지막 화면의 참가 번호를 참가자에게 알려 주었다(철회용). 대본 B 를 읽었다.
- [ ] 진행자 화면에서 그 참가자가 '완료'로 보인다.

## 회차 뒤

- [ ] 기술 문제·절차 위반이 있었다면, 진행자 화면에서 사전 기준 번호와 함께 '제외'를 눌러 사유를 남겼다(결과를 보고 판단하지 않음).
- [ ] 참가자가 철회를 요청하면 '철회(기록 삭제)'를 눌렀다. 남는 감사 기록은 번호와 시각뿐이다.
- [ ] 동의서는 기록과 따로, 잠기는 곳에 보관했다.

## 모집이 끝난 뒤

- [ ] 분석 대상 완료자가 사전 등록한 N명인지 진행자 화면에서 확인했다. 조건 순서가 거의 반반인지도 확인했다.
- [ ] `npm run study:analyze -- data/study --out report.md --csv trials.csv`
- [ ] 보고서를 사전 등록과 대조해, 정한 분석만 '확증'으로 쓰고 나머지는 '탐색'으로 표시했다.
- [ ] 결과를 방향과 관계없이 공개했다(KPI 미달 포함).
- [ ] 보관 기간이 지나면 `data/study/` 를 지운다.
